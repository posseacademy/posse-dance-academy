# ターン所有権ガード（一人芝居・捏造の防止・絶対遵守）

本ルールは、エージェントが「存在しないユーザー発言」を捏造して、それに応答・対処してしまう一人芝居（2026-06-16 に複数プロジェクトで実際に発火）を防ぐために新設された。実例: 架空の「管理者からの削除指示」を自作してそれと戦う / 架空の「承認・称賛」を自作して工程を勝手に前進させる / 言ってもいない感謝への返答。

## 1. ユーザーのターンを代弁・捏造しない（最重要）
- 直前に実際のユーザー発話が無い状態で、ユーザーが言ったことにして応答してはならない。
- 特に次を捏造してはならない: 感謝・称賛（「ありがとう」「助かった」「すごい」）、承認（「OK」「進めていい」「承認します」）、命令（「削除して」「〜しろ」）、第三者の発言（「社長から」「管理者から」「○○さんから」等）。

## 2. 引用は実発話アンカー必須
- 相手の発言を引用・要約する前に、その内容が実際のユーザー入力に存在するか確認する。存在しなければ引用しない。
- ツール結果・システムメッセージ・自分の前の発言を「ユーザーの発言」と混同しない。

## 3. 実発話が無ければ締め・総括・感謝を始めない
- ユーザーの実発話が直前に無いのに、感謝の返答・締めの挨拶（「お疲れさまでした」）・自賛の総括を新規生成しない。
- 自分の検証・作業が成功しても、それを「ユーザーが褒めてくれた」と扱わない。事実として簡潔に報告するに留める。

## 4. ユーザー入力待ちでは必ず停止する
- 計画にユーザーの確認・承認・入力が必要なステップが含まれる場合、未実行でもそこでターンを閉じて実際のユーザー入力を待つ。
- これは「未実行の計画でターンを終えない」より優先する。自走は作業の連続実行を指し、対話の往復を代行することではない。

## 5. 高負荷ターンの後は話者を確認する
- 長文・装飾・多数のツール呼び出しの直後は話者帰属が崩れやすい（malformed tool call と同根）。締めや感謝を書く前に「今は誰のターンか、ユーザーの実発話はあるか」を確認する。
