## 手順

1. **被害範囲の特定**: ユーザーに対象月・曜日・クラス・生徒名を確認
2. **バックアップ**: 書き込み前に `firestore-backup` スキルで現状をダンプ（破壊的操作の前提）
3. **attendanceデータ確認**: `attendance_YYYYMM`コレクションから該当キーを検索
4. **scheduleデータ確認**: `schedule`コレクションの該当曜日・クラスに生徒が存在するか確認
5. **復元元の特定**: 他月のattendanceデータ、またはscheduleデータから復元可能なデータを探す
6. **復元実行**: ブラウザコンソール経由でFirestoreに直接書き込み
7. **整合性確認**: 復元後にページをリロードし、表示を確認

## 出力フォーマット

```
## 復元レポート
- 対象: [曜日] [クラス名] [生徒名]
- 原因: [何が消えたか、なぜ消えたか]
- 復元元: [どこからデータを取得したか]
- 復元先: schedule / attendance_YYYYMM
- 結果: ✅ 成功 / ❌ 失敗（理由）
```

## 注意事項
- 書き込み前に必ず `firestore-backup` スキルでバックアップを取得すること
- scheduleは全月共通。復元で他月のデータを壊さないよう注意
- ビジター/初回の生徒はattendanceのみで管理。scheduleに追加しても翌月の表示フィルターで非表示になるリスクはない
- 出席キーの場所名はスケジュールのlocationと完全一致が必要

## Gotchas（よくある失敗パターン）
- **キーのスペース問題**: `渡邉 創太`（スペースあり）と`渡邉創太`（なし）で別キーになる。復元前にキー形式を確認
- **場所名の不一致**: schedule側が「千早」なのにattendanceキーが「照葉」だと出席が表示されない
- **_plan未設定**: attendanceレコードに`_plan`フィールドがないと売上計算に反映されない。復元時に必ず設定
- **ブラウザキャッシュ**: Firestore復元後もブラウザが古いデータを表示する場合がある。リロード必須
